# 03. 外部データ・API連携

以前のドキュメントは「連携予定」のデータソースを列挙したものだったが、現在は以下が**実際にコードから呼び出されて動いている**。

## 国土地理院(GSI)API

| API | 用途 | 呼び出し箇所 |
| --- | --- | --- |
| 住所検索(`msearch.gsi.go.jp/address-search/AddressSearch`) | 場所指定フォームでの住所・キーワード検索 | `app/src/components/LocationPicker.tsx` |
| 逆ジオコーディング(`mreversegeocoder.gsi.go.jp/reverse-geocoder/LonLatToAddress`) | ピン位置→区名+町丁目名の取得 | `LocationPicker.tsx`、`app/prisma/ingest/fetchParks.ts`(緯度経度が空の行の補完) |

いずれもAPIキー不要・無償。住所検索の結果は「東京都」で始まるものだけに絞り込んでいる(他県の同名地名が混ざらないようにするため)。

## 地図タイル

| スタイル | 提供元 | 用途 |
| --- | --- | --- |
| OpenStreetMap標準タイル(既定) | `tile.openstreetmap.org` | 公園・施設名のラベル密度が高く見やすいため、GSI標準地図から変更 |
| GSI航空写真(`seamlessphoto`) | 国土地理院 | 新規提案フォームでワンタップ切り替え可能な航空写真表示 |

定義は`app/src/lib/mapStyle.ts`(`getOsmMapStyle()`等の関数として実装。MapLibreがstyleオブジェクトを内部で書き換えるため、呼び出しごとに新しいオブジェクトを返す設計にしている)。OSMタイルは[利用ポリシー](https://operations.osmfoundation.org/policies/tiles/)上、大規模な商用トラフィックには自前タイルサーバーへの切り替えが必要(本番化時の検討事項)。

## 東京都オープンデータ(管轄自動判定の実データ)

**公園データ**: 東京都オープンデータカタログサイトのCKAN API(`catalog.data.metro.tokyo.lg.jp/api/3/action/package_search`)経由で、区市町村ごとに公開されている標準データセット「都市公園一覧」CSVを検索・取得する。

- 実行スクリプト: `app/prisma/ingest/fetchParks.ts`(`npm run ingest:parks`)
- CSVの列: `名称, 所在地_連結表記, 緯度, 経度, ...`(標準パターン)。緯度経度が空の行は、GSI住所検索APIでオフライン・ジオコーディングして補完する。
- ファイル名パターン(`(\d{6})_[a-z0-9]+_toshitori(tu|tsu)kouen.csv`、ローマ字表記の「toritu」「toritsu」揺れを許容)に一致するCSVを自動検出する。**23区中16区**がこのパターンで発見できる。
- 上記パターンに一致しないが個別調査で実在を確認できたCSVは`EXTRA_WARD_CSV_URLS`に手動登録する(目黒区: data.bodik.jp上の「都立公園」「区立公園」2データセット、Shift_JISエンコード。中野区: 区独自ポータルwagmap.jp上の「公園配置図」、列名が「公園名」)。列名の表記ゆれ(`名称`/`公園名`、`所在地_連結表記`/`所在地`/`公園所在地`)とエンコーディング(UTF-8/Shift_JIS自動判定)の両方に対応している。
- **23区中18区・約3,700件を取り込み済み**(世田谷・練馬・大田・杉並・渋谷・新宿・江東・品川・墨田・文京・台東・中央・葛飾・足立・千代田・荒川・目黒・中野)。残り5区(港・豊島・北・板橋・江戸川)はカタログ上で該当CSVを発見できなかった(未公開、または個別調査でも発見できなかった別形式で公開されている可能性がある)。
- 取り込みは冪等(同名・同区の施設が既にあればスキップ)。再実行すれば未取得分から続きを取り込める。

**担当部署データ**: `app/prisma/ingest/seedAuthorities.ts`(`npm run ingest:authorities`)で、東京都全域(建設局・環境局)と23区分の担当部署ロースターを投入する。世田谷区・目黒区・渋谷区・中野区・荒川区・港区・豊島区・北区・板橋区・江戸川区(計10区)は各区公式サイトで実在する部署名を確認して採用。残り13区は正式名称を個別確認できていないため、部署名に「(要確認)」を付けて表示する(推測の部署名を確定情報として提示しないため)。連絡先メールアドレスはどの部署も公開されたものが見つからなかったため、全て未設定。

## 未接続・見送ったもの

- **国土交通省「国土数値情報」道路データ(N01)**: 都道/区道の判別に使える唯一の現実的な構造化データだが、実際に探したところ生きたダウンロードリンクが見つからなかった(代替のN06は高速道路専用で対象外)。東京都建設局の道路台帳もスキャン地図のみで機械可読データが無い。道路の管轄判定自体は、都民が「公道として投稿」を選ぶ形で住所(区)ベースにルーティングする方式で別途解決済み(詳細は[05-roadmap.md](./05-roadmap.md))。`PublicSite`の道路データ(`kind: "road"`)は既存の手打ち4件のまま。
- **実際のメール送信**: SMTP等のメール送信サービスは未接続。`NotificationLog`に「誰宛に送る予定か」を記録するのみ。

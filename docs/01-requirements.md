# 01. 実装済み機能一覧

「Should」「将来」ではなく、**現在のコードで実際に動く機能**を対象範囲別にまとめる。ファイルパスは `app/src/` を起点とする。

## 都民向け(`app/(citizen)`)

| 機能 | 画面 | 補足 |
| --- | --- | --- |
| ログイン(開発用スタブ) | `/dev-login` | 本番はLINEログインを想定。ローカル開発中はデモユーザーを選択してログイン |
| マップ/ホーム | `/map` | ヒーロー、統計タイル、「実現しました」自動スクロールカルーセル、署名が多い順/新着順カルーセル、地図(補助的な閲覧手段) |
| 提案一覧 | `/proposals` | 新着順/署名が多い順の並び替え、カテゴリ絞り込みチップ |
| 提案詳細 | `/proposals/[id]` | 写真ギャラリー(最大5枚)、進捗ステッパー、署名ボタン、管轄先の表示 |
| 新規提案作成 | `/proposals/new` | ジャンル選択→タイトル→詳細→写真(1〜5枚)→場所、の5ステップ構成フォーム |
| 場所指定 | `LocationPicker` | 地図クリック/ドラッグ/施設名検索/住所検索のいずれでも、近くの施設・道路を自動認識して区・施設名欄を自動入力する |
| 署名 | `signProposal`アクション | 1ユーザー1提案につき1署名まで(重複防止) |
| マイページ | `/mypage` | 自分が投稿した提案、署名した提案の一覧 |

### 新規提案フォームの制約

- カテゴリは「私有地緑化」を除く4種類のみ選択可能(`CREATABLE_CATEGORIES`)。
- 場所は`PublicSite`(公有地の施設・道路マスタ)に登録済みの地点のみ選択可能(自由な座標では投稿できない)。
- 写真は1〜5枚必須。

## 行政向け(`app/admin`)

| 機能 | 画面 | 補足 |
| --- | --- | --- |
| ログイン(開発用スタブ) | `/admin/login` | 都民向けログインとは別画面 |
| ダッシュボード | `/admin` | 優先度スコア(署名スコア+オープンデータスコア)順の一覧。管轄・判定方法バッジも表示 |
| 提案詳細 | `/admin/[id]` | 本名・優先度スコア内訳・進捗ステッパー・送信予定(通知ログ)を表示、ステータス変更操作 |
| ステータス変更 | `changeStatus`アクション | `STATUS_TRANSITIONS`で許可された遷移のみ実行可能 |

管理画面は行政職員アカウント(`userType: "admin"`)のみアクセス可能(`admin/(protected)/layout.tsx`でガード)。

## 提案のステータス遷移

```
draft → collecting → screening → adopted → in_progress → completed
                         └──────────┴─────────→ rejected
```

## 管轄自動判定(F9)

投稿された場所(緯度経度・自動取得される区名)から、担当する行政部署を自動的にラベル付けする。判定方法は3段階のフォールバック:

1. **施設・道路の近傍一致**(`site_match` / `road_match`) — 東京都オープンデータで取り込んだ実際の公園・図書館・道路データとの距離比較(80m以内)
2. **区フォールバック**(`ward_fallback`) — 施設が見つからなくても、GSI逆ジオコーディングで区がわかれば区の担当部署へ
3. **従来の土地種別による固定表**(`manual_review`) — 上記いずれも不可の場合の最終フォールバック

詳細ロジックは [02-data-model.md](./02-data-model.md) の`Jurisdiction`/`Authority`、[03-external-integration.md](./03-external-integration.md) を参照。

# 06. 都民向け/行政向けの情報の見え方の違い(プライバシー設計)

GreenVoice TOKYOは同じデータベースを都民向け画面(`app/src/app/(citizen)`)と行政向け画面(`app/src/app/admin`)の両方から参照するが、**個人が特定できる情報は行政向け画面にしか出さない**設計を徹底している。

## 基本方針

- `User.displayName`(本名)は行政ダッシュボード・詳細ページのみで取得・表示する。
- 都民向け画面はすべて`User.handle`(公開ID。例:「都民-8821」)のみを取得・表示する。
- 署名者個人の情報は、都民向け・行政向けどちらにも一切渡さない(署名数のみ集計して表示)。

## 実装上の担保

Prismaクエリの`select`/`include`で、都民向けページは常に`user: { select: { handle: true } }`のように絞り込み、行政向けページのみ`select: { displayName: true, handle: true }`のように本名を含める。これは各ページのコンポーネント冒頭のコメントで明示している(例: `(citizen)/proposals/[id]/page.tsx`、`admin/(protected)/[id]/page.tsx`)。

## フィールド別の扱い

| フィールド | 都民向け | 行政向け | 備考 |
| --- | --- | --- | --- |
| 提案者の表示名 | ハンドルのみ | 本名+ハンドル | |
| ステータス変更者 | ハンドルのみ | 本名 | `StatusHistory.changedByUser` |
| 署名者一覧 | 非表示 | 非表示 | 件数のみ集計。どちらの画面にも個人名は出さない |
| 管轄(`Jurisdiction`) | 表示(判定方法バッジ付き) | 表示(判定方法バッジ付き) | 双方が同じ`Jurisdiction`を取得 |
| 優先度スコア内訳 | 非表示 | 表示 | 都民向けは署名数のみ表示 |
| 送信予定ログ(`NotificationLog`) | 非表示 | 表示 | 実送信はしていない(誰に送る予定かのログのみ) |

## 認証・アクセス制御

- 都民向け・行政向けでログイン画面が分離している(`/dev-login`と`/admin/login`)。
- 行政向け画面は`admin/(protected)/layout.tsx`で`userType === "admin"`をガードしており、都民アカウントではアクセスできない。
- 逆に行政職員アカウントで都民向け画面(提案投稿・署名)を使うこと自体は技術的に制限していない(開発用スタブ認証の簡略化。本番実装時は要検討)。
- 行政職員アカウント同士でも、`AdminRole.authorityId`によって見える範囲が分かれる。世田谷区担当のアカウントには世田谷区の公園に関する提案(`Jurisdiction.authorityId`が一致するもの)しか見えず、他区の提案は一覧にも詳細ページ(直接URLアクセス含む)にも表示されない。`authorityId`が未設定のアカウント(全域担当)のみ全件を閲覧・操作できる。
